## :fast_forward: Updating Manually

When a new consensus client release is available, update to the latest stable version. The following procedures show you how to update your beacon node and validator client.

Prior to updating, always review release notes. Changes may require your attention.

* [Lighthouse](https://github.com/sigp/lighthouse/releases)
* [Lodestar](https://github.com/ChainSafe/lodestar/releases)
* [Nimbus](https://github.com/status-im/nimbus-eth2/releases)
* [Prysm](https://github.com/OffchainLabs/prysm/releases)
* [Teku](https://github.com/Consensys-Incorporated/teku)

Follow the procedure for your consensus client:

* [Lighthouse](#Lighthouse)
* [Lodestar](#Lodestar)
* [Nimbus](#Nimbus)
* [Prysm](#Prysm)
* [Teku](#Teku)

### Lighthouse

<details>

<summary>Option 1 - Downloading Binaries</summary>

To download the latest Linux release, extract the archive and clean up, type:

```bash
RELEASE_URL="https://api.github.com/repos/sigp/lighthouse/releases/latest"
BINARIES_URL="$(curl -s $RELEASE_URL | jq -r ".assets[] | select(.name) | .browser_download_url" | grep x86_64-unknown-linux-gnu.tar.gz$)"

echo Downloading URL: $BINARIES_URL

cd $HOME
# Download
wget -O lighthouse.tar.gz $BINARIES_URL
# Untar
tar -xzvf lighthouse.tar.gz -C $HOME
# Clean up
rm lighthouse.tar.gz
```

To stop services, type:

```bash
sudo systemctl stop consensus.service validator.service
```

To remove old binaries, install new binaries and restart services, type:

```bash
sudo rm /usr/local/bin/lighthouse
sudo mv $HOME/lighthouse /usr/local/bin/lighthouse
sudo systemctl start consensus.service validator.service
```

</details>

<details>

<summary>Option 2 - Compiling Source Code</summary>

To download the latest source code, type:

```bash
cd ~/git/lighthouse
git fetch --all && git checkout stable && git pull
```

To compile binaries, type:

```bash
make
```

<center><strong>OR</strong></center>

To compile binaries using the `maxperf` profile, type:

```bash
PROFILE=maxperf make
```

:::note
While increasing compile time, using the `maxperf` profile improves some Lighthouse benchmarks by about 20 percent.
:::

In case of compilation errors, type:

```bash
rustup update
cargo clean
make
```

To verify that Lighthouse compiled correctly, type:

```
lighthouse --version
```

To stop services, type:

```bash
sudo systemctl stop consensus.service validator.service
```

To remove old binaries, install new binaries and restart services, type:

```bash
sudo rm /usr/local/bin/lighthouse
sudo cp $HOME/.cargo/bin/lighthouse /usr/local/bin/lighthouse
sudo systemctl start consensus.service validator.service
```

</details>

### Lodestar

<details>

<summary>Option 1 - Downloading Binaries</summary>

To download the latest Linux release, extract the archive and clean up, type:

```bash
RELEASE_URL="https://api.github.com/repos/ChainSafe/lodestar/releases/latest"
LATEST_TAG="$(curl -s $RELEASE_URL | jq -r ".tag_name")"
BINARIES_URL="https://github.com/ChainSafe/lodestar/releases/download/${LATEST_TAG}/lodestar-${LATEST_TAG}-linux-amd64.tar.gz"
	
echo Downloading URL: $BINARIES_URL

cd $HOME
# Download
wget -O lodestar.tar.gz $BINARIES_URL
# Untar
tar -xzvf lodestar.tar.gz -C $HOME
# Clean up
rm lodestar.tar.gz
```

To stop services, type:

```bash
sudo systemctl stop consensus.service validator.service
```

To remove old binaries, install new binaries and restart services, type:

```bash
sudo rm -rf /usr/local/bin/lodestar && sudo mkdir -p /usr/local/bin/lodestar
sudo mv $HOME/lodestar /usr/local/bin/lodestar
sudo systemctl start consensus.service validator.service
```

</details>

<details>

<summary>Option 2 - Compiling Source Code</summary>

To download the latest source code and compile binaries, type:

```bash
cd ~/git/lodestar
git checkout stable && git pull
yarn install
yarn run build
```

In case of compilation errors, type:

```bash
yarn clean:nm && yarn install
```

To verify that Lodestar compiled correctly, type:

```bash
./lodestar --version
```

The `lodestar --version` command displays output similar to:

```
🌟 Lodestar: TypeScript Implementation of the Ethereum Consensus Beacon Chain.
  * Version: v1.8.0/stable/a4b29cf
  * by ChainSafe Systems, 2018-2022
```

To stop services, type:

```bash
sudo systemctl stop consensus.service validator.service
```

To remove old binaries, install new binaries and restart services, type:

```bash
sudo rm -rf /usr/local/bin/lodestar
sudo cp -a $HOME/git/lodestar /usr/local/bin/lodestar
sudo systemctl start consensus.service validator.service
```

</details>

### Nimbus

<details>

<summary>Option 1 - Downloading Binaries</summary>

To download the latest Linux release, extract the archive and clean up, type:

```bash
RELEASE_URL="https://api.github.com/repos/status-im/nimbus-eth2/releases/latest"
BINARIES_URL="$(curl -s $RELEASE_URL | jq -r ".assets[] | select(.name) | .browser_download_url" | grep _Linux_amd64.*.tar.gz$)"

echo Downloading URL: $BINARIES_URL

cd $HOME
# Download
wget -O nimbus.tar.gz $BINARIES_URL
# Untar
tar -xzvf nimbus.tar.gz -C $HOME
# Rename folder
mv nimbus-eth2_Linux_amd64_* nimbus
# Clean up
rm nimbus.tar.gz
```

To stop services, type:

```bash
sudo systemctl stop consensus.service
# If running a standalone Nimbus validator
sudo systemctl stop validator.service
```

To remove old binaries, install new binaries, clean up and restart services, type:

```bash
sudo rm /usr/local/bin/nimbus_beacon_node
sudo rm /usr/local/bin/nimbus_validator_client
sudo mv nimbus/build/nimbus_beacon_node /usr/local/bin
sudo mv nimbus/build/nimbus_validator_client /usr/local/bin
rm -r nimbus
sudo systemctl start consensus.service
# If running a standalone Nimbus validator
sudo systemctl start validator.service
```

:::note
If you configure Nimbus to use a combined beacon node and validator client, then the `validator.service` file does not exist.
:::

</details>

<details>

<summary>Option 2 - Compiling Source Code</summary>

To download the latest source code and compile binaries, type:

```bash
cd ~/git/nimbus-eth2
git checkout stable && git pull
make -j$(nproc) update
make -j$(nproc) nimbus_beacon_node
make -j$(nproc) nimbus_validator_client
```

To verify that Nimbus compiled correctly, type:

```bash
cd $HOME/git/nimbus-eth2/build
./nimbus_beacon_node --version
```

To stop services, type:

```bash
sudo systemctl stop consensus.service
# If running a standalone Nimbus validator
sudo systemctl stop validator.service
```

To remove old binaries, install new binaries, clean up and restart services, type:

```bash
sudo rm /usr/local/bin/nimbus_beacon_node
sudo rm /usr/local/bin/nimbus_validator_client
sudo cp $HOME/git/nimbus-eth2/build/nimbus_beacon_node /usr/local/bin
sudo cp $HOME/git/nimbus-eth2/build/nimbus_validator_client /usr/local/bin
sudo systemctl start consensus.service
# If running a standalone Nimbus validator
sudo systemctl start validator.service
```

:::note
If you configure Nimbus to use a combined beacon node and validator client, then the `validator.service` file does not exist.
:::

</details>

### Prysm

<details>

<summary>Option 1 - Downloading Binaries</summary>

To download the latest binaries, type:

```bash
cd $HOME
prysm_version=$(curl -f -s https://prysmaticlabs.com/releases/latest)
file_beacon=beacon-chain-${prysm_version}-linux-amd64
file_validator=validator-${prysm_version}-linux-amd64
curl -f -L "https://prysmaticlabs.com/releases/${file_beacon}" -o beacon-chain
curl -f -L "https://prysmaticlabs.com/releases/${file_validator}" -o validator
chmod +x beacon-chain validator
```

To stop services, type:

```bash
sudo systemctl stop consensus.service validator.service
```

To remove old binaries, install new binaries and restart services, type:

```bash
sudo rm /usr/local/bin/beacon-chain
sudo rm /usr/local/bin/validator
sudo mv beacon-chain validator /usr/local/bin
sudo systemctl start consensus.service validator.service
```

</details>

<details>

<summary>Option 2 - Compiling Source Code</summary>

To download the latest source code and compile binaries, type:

```bash
cd $HOME/git/prysm
git fetch --tags
RELEASETAG=$(curl -s https://api.github.com/repos/OffchainLabs/prysm/releases/latest | jq -r .tag_name)
git checkout tags/$RELEASETAG
go build -o=./build/beacon-chain ./cmd/beacon-chain
go build -o=./build/validator ./cmd/validator
```

To stop services, type:

```bash
sudo systemctl stop consensus.service validator.service
```

To remove old binaries, install new binaries and restart services, type:

```bash
sudo rm /usr/local/bin/beacon-chain
sudo rm /usr/local/bin/validator
sudo cp $HOME/git/prysm/build/beacon-chain /usr/local/bin
sudo cp $HOME/git/prysm/build/validator /usr/local/bin
sudo systemctl start consensus.service validator.service
```

</details>

### Teku

<details>

<summary>Option 1 - Downloading Binaries</summary>

To download the latest Linux release, extract the archive and clean up, type:

```bash
RELEASE_URL="https://api.github.com/repos/Consensys-Incorporated/teku/releases/latest"
LATEST_TAG="$(curl -s $RELEASE_URL | jq -r ".tag_name")"
BINARIES_URL="https://artifacts.consensys.net/public/teku/raw/names/teku.tar.gz/versions/${LATEST_TAG}/teku-${LATEST_TAG}.tar.gz"
echo Downloading URL: $BINARIES_URL

cd $HOME
# Download
wget -O teku.tar.gz $BINARIES_URL
# Untar
tar -xzvf teku.tar.gz -C $HOME
# Rename folder
mv teku-${LATEST_TAG} teku
# Clean up
rm teku.tar.gz
```

To stop services, type:

```bash
sudo systemctl stop consensus.service

# If running a standalone Teku validator
sudo systemctl stop validator.service
```

To remove old binaries, install new binaries and restart services, type:

```bash
sudo rm -rf /usr/local/bin/teku
sudo mv $HOME/teku /usr/local/bin/teku
sudo systemctl start consensus.service

# If running a standalone Teku validator
sudo systemctl start validator.service
```

</details>

<details>

<summary>Option 2 - Compiling Source Code</summary>

To download the latest source code and compile binaries, type:

```bash
cd ~/git/teku
# Get new tags
git fetch --tags
RELEASETAG=$(curl -s https://api.github.com/repos/Consensys-Incorporated/teku/releases/latest | jq -r .tag_name)
git checkout tags/$RELEASETAG
./gradlew distTar installDist
```

To verify that Teku compiled correctly, type:

```shell
cd $HOME/git/teku/build/install/teku/bin
./teku --version
```

To stop services, type:

```bash
sudo systemctl stop consensus.service

# If running a standalone Teku validator
sudo systemctl stop validator.service
```

To remove old binaries, install new binaries and restart services, type:

```bash
sudo rm -rf /usr/local/bin/teku
sudo cp -a $HOME/git/teku/build/install/teku /usr/local/bin/teku
sudo systemctl start consensus.service

# If running a standalone Teku validator
sudo systemctl start validator.service
```

</details>

### Verifying Validator Attestations

<p class="pi">To verify that your validator is submitting attestations successfully:</p>

<ol>
  <li>Visit a blockchain explorer for the network where you are operating a node—[Hoodi Testnet](https://hoodi.beaconcha.in/) or [Mainnet](https://beaconcha.in/).</li>
      
  <li>In the Search field, copy and paste the public key for your validator.</li>
  <li>In the search results, look for successful attestations.</li>
</ol>
